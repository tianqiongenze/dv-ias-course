## 1. 课程定位与设计理念

### 1.1 课程定位

本课程以校企合作真实交付的**数字乡村综合服务平台（DV-IAS）**为载体——该项目已在两台服务器 K8s 集群上完成部署验收：18 个容器化负载在线、GraphQL 联邦网关全链路贯通、1.058 亿行测试数据、k6 350VU 压测 0 失败、Playwright 自动化 E2E 12/12 通过。学生以"新入职工程师"身份进入项目，在双导师（校内教授级高工 + 企业资深架构师）带领下完成从需求理解到上线运维的完整工程闭环。

**先行课程**：Python 程序设计、MySQL 数据库、Linux 基础、Web 前端基础、计算机网络。
**后续课程**：毕业设计、顶岗实习、1+X 云计算/大数据运维认证。

### 1.2 德国双元制本土化设计

| 双元制要素 | 本土化落地 |
|---|---|
| 双元主体（学校+企业） | 校内理论教师 + 企业架构师双导师；企业方提供真实工程文档与验收标准 |
| 学习领域→学习情境 | 6 个学习领域（见 §3），每个领域以 DV-IAS 真实任务单驱动 |
| 工作过程系统化 | 每次课 = 资讯→计划→决策→实施→检查→评价 六步法 |
| 行动导向 | 学生 4 人一组模拟"项目小队"，角色轮换（PO/后端/前端/测试） |
| 企业实训（Lehrauftrag） | 第 13-16 次课在企业导师主导下进行上线演练与故障复盘 |
| 手工证明（Arbeitsprobe） | 每次课产出可验证工件（代码/文档/测试报告），纳入成长档案 |

### 1.3 配套教学法

| 方法 | 应用场景 |
|---|---|
| **费曼学习法** | 每次课"讲给别人听"环节：学生用 3 分钟向搭档讲解本次课核心概念，讲不清即回炉 |
| **布鲁姆认知模型** | 每次课目标按"记忆→理解→应用→分析→评价→创造"六层标注，考核对齐"创造"层 |
| 完整行动六步法 | 每张任务单均含六步栏目 |
| 项目引导文（Leittext） | 自学材料包 + 自检问题清单 |
| 同伴互评（Peer Review） | 代码走查、答辩互评双盲打分 |

## 2. 课程目标

### 2.1 素质目标（思政融合）

1. 数字乡村振兴使命感：理解"数字乡村"国家战略与技术服务社会的价值
2. 工程伦理与数据安全：个人隐私保护（SM4 加密）、等保合规意识
3. 团队协作与工匠精神：代码规范、文档意识、精益求精
4. 双元职业素养：守时、日报、任务闭环等企业化习惯

### 2.2 知识目标（布鲁姆：记忆/理解）

1. 陈述数字乡村平台"1+1+N"架构与 GraphQL Federation 数据流
2. 解释 DDD 限界上下文、读写分离、多级缓存（L1/L2/网关）的原理
3. 说出国密 SM3/SM4 在登录与字段加密中的作用
4. 描述 K8s Deployment/Service/HPA/ConfigMap 的关系

### 2.3 能力目标（布鲁姆：应用/分析/评价/创造）

1. 【应用】能使用 Docker 构建镜像、编写 K8s 清单部署微服务
2. 【应用】能编写 GraphQL 查询/变更完成全链路业务操作
3. 【分析】能解读 Prometheus 监控与 k6 压测报告，定位性能瓶颈
4. 【评价】能依据验收标准评审同伴的接口设计与测试用例
5. 【创造】能独立设计并实现一个新业务场景（如"农资兑换"）从 API 到上线的完整增量

## 4. 考核评价方案（双元制多元评价）

| 评价维度 | 占比 | 评价者 | 工具 |
|---|---|---|---|
| 过程性：任务单+工时日志 | 20% | 校内导师 | 每次课任务单评分表 |
| 过程性：费曼讲解+课堂表现 | 10% | 同伴+导师 | 费曼卡互评 |
| 阶段性：3 次阶段实作（L2/L3/L5 各一次） | 30% | 双导师 | 实作评分标准（Rubric） |
| 终结性：综合项目答辩 | 30% | 企业导师主考 | 答辩评分表（功能40/工程30/表达15/应变15） |
| 素养：考勤与职业习惯 | 10% | 校内导师 | 双元日报签到 |

**通过标准**：总分 ≥60 且综合答辩 ≥60；答辩实行企业导师一票否决制（模拟企业验收）。
