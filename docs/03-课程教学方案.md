# 《数字乡村综合服务平台项目实战》课程教学方案

> 双元制行动导向 + 费曼学习法 + 布鲁姆认知模型 ｜ 64 课时 ｜ 与授课计划（02 号）一一对应
> 本方案给出**通用教学组织范式**与**分次课教学要点**，教师可直接按此授课。

---

## 1. 总体教学组织范式（每次课通用）

### 1.1 课堂时空结构（4 课时 = 180 分钟）

```
┌─ 课时1：资讯(Erwunden) 45min ─ 导入情境+自学引导文+关键提问
├─ 课时2：计划+决策(Planen/Entscheiden) 45min ─ 小队定方案+导师质询（决策门槛）
├─ 课时3：实施(Durchführen) 45min ─ 动手产出工件（代码/文档/实验）
│    └─ 末 15min：★费曼环节★ 两两互讲，讲不清者登记"回炉清单"
└─ 课时4：实施+检查+评价 45min ─ 完成工件+自检表+同伴互评+导师点评
```

### 1.2 费曼学习法操作规程（每次课固定 15 分钟）

1. **配对**：A/B 两人一组，轮换"讲解者/听众"
2. **讲**：讲解者 3 分钟讲清本次课核心概念（不看书、可用白板）
3. **问**：听众必须提 1 个"为什么"问题
4. **卡**：填《费曼卡》：`我能讲清的 / 我讲卡的 / 我回去要补的`
5. **回炉**：讲卡点被记录 ≥2 次的概念，导师在下节课开头 5 分钟重讲

### 1.3 布鲁姆目标对齐检查表（导师备课用）

- 每次课的**任务单验收题**必须至少触及"分析"层
- 阶段实作与答辩必须触及"创造/评价"层
- 禁止以"复述"类问题作为唯一验收手段

### 1.4 双元制角色与责任矩阵

| 活动 | 校内导师 | 企业导师 | 学生小队 |
|---|---|---|---|
| 任务单发放与验收 | ● | ○ | ● 执行 |
| 生产案例复盘 | ○ | ● | ● 参与 |
| 代码走查 | ● | ○（抽查） | ● 互评 |
| 答辩主考 | ○ | ● | ● |
| 成长档案归档 | ● | ○ | ● 提交 |

●=主责 ○=参与

## 2. 分次课教学要点（16 次）

### 第 1 次：开班 + 项目全景

- **情境导入**：放映 DV-IAS 生产环境截图（大屏/H5/压测报告），宣布"你们是第 2 期迭代的新员工"
- **找茬活动**：发原始《建设方案.pdf》节选（含 5 大缺陷），小队 10 分钟找问题，对照 00 号文档规避表
- **组队**：4 人/队，角色 PO/后端/前端/测试，发小队章程模板
- **费曼题**：向搭档讲清"这个平台有哪三大端、各给谁用"
- ⚠️ 注意：强调企业守则——文档、代码、账号密码不得外传

### 第 2 次：架构解码

- 引导文：只读 00 号文档 §3-4 与 03 号文档 §BDAT 四架构
- 关键提问：为什么用 GraphQL Federation 而不是单体 REST？（限界上下文/独立部署/按需取数）
- 实施要求：架构图必须画出 8 个子图 + 网关 + TiDB/Redis 位置与数据流箭头
- 评价：两图互评（完整性/准确性/可表达性三项 1-5 分）

### 第 3 次：数据底座设计

- 关键提问：为什么选 TiDB 而不是 MySQL 主从？（HTAP/水平扩展/在线变更）
- 实作题：为"农资兑换"场景设计 3 张表（商品/兑换单/流水），要求含幂等唯一键
- 常见错误：主键用业务含义字符串、缺 created_at、无索引——逐一讲评

### 第 4 次：1 亿行数据填充

- 演示先行：导师现场展示 bulk-gen Job 与 `kubectl logs` 进度
- 分析题：为什么用 SHARD_ROW_ID_BITS=4 PRE_SPLIT_REGIONS=8？（打散热点+预分裂 Region）
- 实作：小队在 team{n}-dev 命名空间跑 Job，核验行数（COUNT 与写入计划一致）
- 安全提示：绝不能在生产库跑 TRUNCATE/DROP——操作前必先 `kubectl get` 确认 namespace

### 第 5 次：多级缓存（含阶段实作一）

- 源码走读：`cache.py` 的 L1 TTL + Redis L2 + 单飞锁（singleflight）+ TTL 抖动
- 实验演示：压掉 Redis 模拟击穿，观察 DB QPS 飙升，再启用单飞对比
- 实作一（10%）：为积分榜 top10 加双层缓存，验收=压测命中率 ≥90%

### 第 6-9 次：DDD 与 GraphQL 联邦主线

- 第 6 次：上下文地图画法（事件风暴简化版：名词→实体→上下文→边界）
- 第 7 次：SDL 契约先行——先写 schema 再写实现；讲 @key 实体与 _resolve_reference
- 第 8 次：Strawberry 代码模板发放，学生仿写；重点踩坑：**federation.Schema(types=[...]) 显式注册实体**（真实生产事故，第 9 次由企业导师复盘）
- 第 9 次（企业日）：复盘"Party 实体不进 SDL → 网关 400"事故链：现象→排查→根因→修复→沉淀；学生接入网关验证自己的农资子图联邦查询

### 第 10-11 次：安全合规主线

- 第 10 次：登录链路拆解 phone_hash(SM3) + password_hash(SM3-PBKDF2 10000 轮) + phone_enc(SM4-GCM)；学生为农资兑换人手机号加同样保护
- 第 11 次：网关三层防线（JWT 校验+身份头注入防伪造 / 令牌桶限流 / INTERNAL 错误脱敏）；分析题：为什么网关要剥离客户端伪造的 x-user-id？MCP 审计落库的意义？

### 第 12-14 次：部署运维主线

- 第 12 次：从 Dockerfile→镜像→Deployment→Service→探针；踩坑案例：探针打在 GraphQL 端口返回 400 → CrashLoop（真实事故）
- 第 13 次（企业日）：四信号（延迟/流量/错误/饱和度）；学生为农资服务配 ServiceMonitor 并自建看板
- 第 14 次（企业日）：k6 场景设计（ramping-vus/constant-vus）与拐点法；学生出压测报告并回答"瓶颈在哪、下一步扩什么"

### 第 15-16 次：质量与答辩

- 第 15 次：E2E 12 用例结构精讲（页面渲染/登录/上报/流转/积分/联邦/问答/拦截）；学生写 3 条农资 E2E 并全量回归
- 第 16 次（企业日）：答辩按企业验收：功能演示 4min + 架构讲述 2min + 压测与测试数据 2min；评委问 5min（含 1 个故障应急题）；企业导师一票否决制说明

| 风险信号 | 干预措施 |
