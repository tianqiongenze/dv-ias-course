# ADR-007 执行期技术决策（迭代0 / 一期MVP）

> 状态：已采纳 ｜ 日期：2026-10-25 ｜ 关联：ADR-001~005（见 03号文档§6）

## 决策1：子图实现语言 Python(Strawberry) 替代 Java(DGS)（仅限迭代0/一期MVP）

- **背景**：02号文档选型 Java 21 + Spring Boot 3 + DGS。执行评估：单构建代理环境下，Java 多模块构建反馈周期 3-8 分钟/次，MVP 交付风险高；集群 fnb-prod 已验证 Python 微服务模式（agent-runtime/mcp-fnb-tools 先例）。
- **决策**：迭代0/一期子图用 Python 3.13 + FastAPI + **Strawberry Federation**（原生支持 Fed2 实体/@key/_resolve_reference），保持 04号文档 DDD 分层（domain/application/adapter 体现在 app/ 模块化）与 06号文档联邦契约不变。网关仍为 Apollo（Gateway Node 版；Apollo Router 为 Rust 二进制，拉取受限时 Gateway 即可满足当前吞吐）。
- **迁移路径**：域服务接口/事件契约（GraphQL SDL + 轮询→Pulsar）已冻结，二期可逐服务替换为 Java DGS 实现而不影响前端与网关（联邦的核心价值）。
- **未变**：GraphQL Federation 2、读写分离（rw/ro 双池）、多级缓存（L1进程+L2 Redis Cluster）、领域事件语义、幂等不变量、国密（SM3口令/SM4字段加密已实现于 szxc_common/crypto.py）。

## 决策2：跨域事件通道 MVP 用"内网HTTP轮询"承载，Pulsar 主题已预建

- governance→points 的 `event.approved` 事件：MVP 用治理服务 `/internal/approved?after=cursor` 幂等拉取（3s 间隔），消费端 `uk_ref` 唯一键防重。Pulsar 租户 `szxc/core` 与 5 个主题已建好，一期硬化时切换 pulsar-client 生产/订阅，语义不变（至少一次+幂等）。
- **理由**：pip pulsar-client 对 py3.13 的 wheel 兼容存在不确定性，不把交付押在二进制依赖上。

## 决策3：TiDB 读写分离 MVP 为"账号级"（szxc_ro 只读），Pod 级读池延后

- 读池当前指向 tidb.infra Service（双 tidb-server 负载均衡），但使用只读账号，误写被权限层阻断。05号文档的"Pod 标签固定读实例"在租户共享 RS 上需 label patch（会被 RS 回收），列入一期硬化（与运维 owner 协调打标或扩一个专用 tidb-server）。

## 决策4：远程医疗/区块链溯源按确认项 C6 执行

- 远程医疗：仅预约+会议链接转接，不存诊疗数据。溯源（二期 trace-svc）：SM3 哈希链 + 日度根哈希公示，非链。

## 决策5：密钥管理 MVP 用 K8s Secret（etcd 加密由平台层保障）

- DB/Redis/JWT/SM4 密钥入 Secret；SM4 字段密钥 MVP 内置于镜像env（默认值），生产轮换路径见 10号文档§3（90天轮换 + Vault/SealedSecrets 演进）。

## 决策6：agent-runtime RAG 检索 MVP 为"进程内语料+二元组打分"

- Milvus collection 与嵌入服务（ollama-embed/bge）已在集群就绪，一期硬化接入（混合检索+重排链路已在 07号文档冻结）。LLM 经 LiteLLM 路由 qwen2.5:14b（本地，数据不出域模式），失败自动降级 FAQ——降级链与生产设计一致。
