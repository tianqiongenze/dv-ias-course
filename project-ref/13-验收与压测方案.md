# 13 验收与压测方案

> 依据：GB/T 25000.51-2016（SQuaRE 就绪可用软件质量要求）+ 本项目 SLO（01 号文档 §5）。

---

## 1. 验收组织

- 三级验收：**迭代验收**（每 2 周，DoD 检查）→ **阶段验收**（一/二期末，甲方 UAT）→ **竣工验收**（全套交付物 + 第三方测试报告 + 等保备案）。
- UAT 甲方参与角色：县农业农村局业务代表 2、村干部代表 3、网信办技术代表 1。

## 2. 功能验收

- 用例来源：04 号文档用例 × 06 号 SDL 契约 × Gherkin 场景库（200+ 条）；
- 通过标准：P0 用例 100% 通过；P1 ≥98%；无未关闭 P0/P1 缺陷；
- 兼容性矩阵：微信（iOS/Android 主流版本）+ H5（Chrome/Edge/Safari 近两年）+ 管理端（1080p/2K）。

## 3. 性能验收（k6 场景集）

### 3.1 场景定义（混合比例按 08 号文档流量画像）

| 场景 | 脚本 | 目标（一期/现硬件） |
|---|---|---|
| S1 公开浏览 | 列表+详情 8:2，思考时间 3-10s | 8,000 VU，P95≤200ms，错误<0.1% |
| S2 事件上报 | 上报→查进度 | 1,000 rps 持续 10min，P95≤400ms |
| S3 投票洪峰 | 阶梯 500→5,000 VU/2min | 一人一票零重复，P95≤500ms |
| S4 AI 问答 | 并发会话 | 40 并发本地模型，首 token≤2s |
| S5 IoT 注入 | 5,000 点/s 30min | 无丢失（对账），消费延迟<5s |
| S6 稳定性 | 混合 30% 负载 8h soak | 无内存增长泄漏、无错误抬升 |
| S7 大屏 | 50 并发大屏 + 快照推送 | 快照≤1s，WS≤1.5s |

### 3.2 执行与判据

- 环境：szxc-prod 同规格压测窗口（夜间），监控全套开启（Grafana 录屏归档）；
- 拐点法：每场景阶梯加压找到吞吐拐点，**拐点流量 ≥ 目标 ×1.5** 视为余量合格；
- 报告：每场景一节（负载、延迟分位、错误、资源曲线、TiDB/Redis/Pulsar 指标、结论），与 08 号预算对照偏差分析。

## 4. 可靠性验收

- 单 Pod kill：服务错误 ≤5s 抖动恢复；
- 单节点宕机演练（窗口期）：核心服务 5min 内恢复承载（HPA+反亲和）；
- 依赖故障注入：Pulsar 停 1min（上报不丢，恢复后补投）；Redis 超时（回源 DB 限流保护）；AI 超时（FAQ 降级）——验证 P8 矩阵；
- 备份恢复演练：BR 恢复到临时实例，RPO≤5min、RTO≤30min 实测记录。

## 5. 安全验收

- 第三方渗透测试：高危 0、中危 ≤3 且限期整改；
- 等保三级：差距分析表全项闭环，测评机构受理回执；
- 依赖扫描：CVSS≥7 为 0；
- AI 红队：越权诱导 50 条 100% 拒绝。

## 6. 数据质量验收

- 主数据六大实体：与村干部台账抽样比对准确率 ≥98%；
- 对账：积分/预约/兑换连续 7 天零差异；
- 指标口径：大屏 20 项指标与手工核算一致（审计留痕）。

## 7. 交付物清单（竣工验收）

1. 源代码（Monorepo，含全部测试）与镜像清单；
2. 部署清单（Kustomize/Helm）+ 参数手册；
3. 全套设计文档（本 docs 目录 v1.0 归档版）+ ADR；
4. 运维手册 + Runbook + 值班表模板；
5. 压测报告、可靠性演练报告、安全测试报告、等保材料；
6. 数据字典 + 指标口径字典 + API 变更日志；
7. 培训材料（管理员/网格员/村民三套）与培训记录；
8. 项目管理产物（计划、风险登记册、变更记录、验收单）。

## 8. 质保与运营移交

- 质保期 12 个月：P0 2h 响应/24h 修复，P1 8h/3 工作日；季度巡检报告；
- 移交：管理员账号交接、Runbook 演练带教 2 次、源码与镜像归档移交清单签字。
