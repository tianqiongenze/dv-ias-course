# 07 AI 智能体平台设计（数字乡村大脑）

> 集群约束：无 GPU。设计原则——"小模型本地跑、大模型网关路由、重计算异步批、一切可降级"。

---

## 1. 平台分层

```
体验层   村民问答 │ 办事助手 │ 治理辅助 │ 大屏播报
编排层   agent-runtime (Python/LangGraph)：意图路由→计划→工具调用→反思→答案(带引用)
能力层   RAG检索(Milvus+BM25) │ 重排(vector-reranker) │ 知识图谱(Nebula) │ 规则引擎
工具层   mcp-dv-tools (MCP)：业务查询/办理 12+ 工具
模型层   LiteLLM(30083) ─▶ Ollama本地(qwen2.5-7b/14b) ─▶ 外部大模型(可配)
        ollama-embed(bge-m3) │ CPU图像(YOLOv8n-int8/PP-LCNet)
```

## 2. 智能体设计（四个 Agent）

| Agent | 输入 | 流程（LangGraph 节点） | 工具(MCP) | 降级 |
|---|---|---|---|---|
| 农技问答 | 自然语言 | 意图分类→混合检索(BM25+向量 top50)→重排 top5→生成(引用)→敏感词审 | search_agri_kb, query_agri_advice, query_weather | 检索失败→规则FAQ；模型超时→模板答案+人工兜底工单 |
| 办事助手 | 自然语言 | 意图→槽位填充(多轮)→资格预检→创建申请/跳转 | search_service_guide, create_cert_request, query_event_progress | 槽位失败→人工客服转接 |
| 治理辅助 | 事件文本+图片 | 文本分类(18类)+紧急度→派单建议(网格画像)→公开合规检查 | 内部 RPC governance-svc | AI 不可用→规则关键词分类 |
| 乡村播报 | 定时/触发 | 指标取数→文稿生成→TTS(edge-tts已有)→大屏/公众号 | metrics, portal_publish(草稿) | 文稿失败→模板播报 |

编排约束：单请求工具调用 ≤3 轮；每步超时 3s；全链路 trace（OTel）记录 prompt/completion 摘要（脱敏）。

## 3. RAG 管道

1. **知识源**：政策法规（指南2.0/行动计划/地方文件）、办事指南、农技知识库、历史处置案例、村规民约。
2. **摄取**：定时任务拉取 → 解析(docx/pdf/html) → 清洗分块（语义分块 256-512 token，重叠 15%）→ bge-m3 嵌入（ollama-embed:11435）→ Milvus collection `szxc_kb`（HNSW，M=16，ef=128）+ TiDB 全文索引（BM25）。
3. **检索**：混合召回（向量 top30 + BM25 top30 RRF 融合）→ vector-reranker(:8090) 重排 top5 → 生成 prompt（限定上下文，带出处 ID）。
4. **评测集**：300 条标注问答（村干部参与），检索命中率 recall@5 ≥85%，答案引用准确率 ≥90% 方可上线；每次知识更新回归。

## 4. 知识图谱（NebulaGraph，space `szxc_kg`）

- 点：人(Party)、户、组织、地块、事件、设备、政策、作物。
- 边：belongsTo(人-户-组-村)、owns(户-地块)、reported/handled(人-事件)、monitors(设备-地块)、applies(政策-作物)。
- 用途：关系穿透查询（"该网格员本月处置关联事件"）、图谱增强 RAG（GraphRAG：实体子图作为生成上下文）、防关系造假（补贴申请人-地块归属校验）。
- 构建：CDC 事件消费 → 增量 upsert（每日全量校准）。

## 5. 图像 AI（CPU 约束下的工程方案）

| 任务 | 模型 | 部署 | 性能预算 | 触发 |
|---|---|---|---|---|
| 垃圾堆放/违停 | YOLOv8n int8 | Python sidecar 服务，2 副本 | 8 核 40 FPS；每帧 640px | 摄像头 5min 截图轮询，非实时视频流 |
| 病虫害分类 | PP-LCNet_x1_0 int8 | 同上 | 单图 <300ms | 用户拍照上传 |
| 全景/图片审核 | NSFW 轻量模型 + 规则 | 同上 | 同上 | 内容发布前 |

原则：**截图轮检而非视频流分析**（成本断崖式下降，满足 PDF 场景 90% 需求）；置信度 <0.7 转人工复核（AI 只立案建议，人权在网格员——AI 辅助而非 AI 裁决）。

## 6. 模型路由与成本治理（LiteLLM）

- 路由策略（LiteLLM 配置）：`问答/分类→本地 qwen2.5-7b`；`长文生成/复杂推理→外部旗舰模型(白天)→本地14b(夜间/超额)`；嵌入恒本地。
- 配额：按租户/用户日 token 限额，超额降级模板；全链路 token 计量入 `dws.llm_usage`（成本可视）。
- 数据安全：外部模型调用经内容脱敏代理（去姓名/身份证/手机号），策略可配置为"纯本地模式"。

## 7. 安全与评测（AI 治理）

- 提示注入防护：工具入参白名单校验、系统提示与用户输入隔离、输出 JSON Schema 校验。
- 敏感词/合规过滤：答案过审词库（涉政/涉稳/医疗建议免责声明）。
- 红队评测集：50 条诱导性 prompt（越权查询他人信息等）必须 100% 拒绝。
- 模型变更走 ADR + 评测门禁，模型卡片登记（用途/限制/评测结果）。
