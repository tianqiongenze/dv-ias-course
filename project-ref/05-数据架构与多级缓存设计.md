### 1.3 读写分离实现（TiDB 专用方案）

集群现状：2×tidb-server。方案（不引入新组件）：

| 通道 | Service | 用途 |
|---|---|---|
| 写主池 | `szxc-tidb-write.infra`（指向 tidb-server-…-2bngs @master） | 所有写事务 + 强一致读（事务内） |
| 读池 | `szxc-tidb-read.infra`（指向 tidb-server-…-pbxt9 @worker1；沿用 fnb-prod `tidb-read` ExternalName 模式） | 无事务读、列表、详情 |
| 分析池 | TiFlash 副本 + `SET tidb_isolation_read_engines='tiflash'` | dws 查询 |

落地机制：
1. 应用侧 Spring 双 `DataSource`（write/read），由仓储层按"事务内→write，事务外只读→read"路由；@Transactional(readOnly=true) 自动走读池。
2. 读池连接使用只读账号（`szxc_ro`），数据库侧兜底防误写。
3. 延迟控制：TiDB 内部raft读延迟毫秒级，业务读池不做过期分支（非异步复制，无主从延迟问题）——这是 TiDB 读写分离优于 MySQL 主从的关键点。
4. 连接池：HikariCP 写池 max 40/读池 max 80 每实例；必要时引入已有 pgbouncer 思路评估 ProxySQL（一期不需要）。

## 2. 多级缓存体系（四层）

```
L0 CDN(建议外购)      静态资源、720°全景、公开页        TTL 1h~1d
L1 Nginx micro_cache  公开类 GraphQL 响应(带public标记) TTL 5~60s
L2 Router 层          APQ 查询缓存 + 响应缓存(Redis)   TTL 5~60s
L3 应用 L1 Caffeine   热点字典/组织树/配置             TTL 30s~5min, 最大 1 万条
L4 应用 L2 Redis      业务对象/列表/计数器             TTL 5~30min + 事件失效
回源: L3 miss → L4 miss → TiDB读池(带锁singleflight防击穿)
```

### 2.1 缓存键与失效策略（Cache-Aside + 事件失效）

| 数据 | Key 模式 | TTL | 失效触发 |
|---|---|---|---|
| 组织树 | `md:org:tree:v{n}` | 30min | `iam.org.changed` 广播删除 |
| 村务公开列表 | `pub:list:{village}:{col}:{page}` | 60s + micro_cache 10s | `portal.content.published` |
| 事件详情 | `gov:evt:{id}` | 5min | 事件状态变更事件 |
| 积分余额 | `pts:bal:{partyId}` | 30min | `points.earned/deducted` 事件 |
| 库存余量 | `trm:slot:{slotId}` | — | Redis 原子扣减（DECR）+ TiDB 对账 |
| 热点榜单 | `dws:rank:*` | 5min | 定时刷新 |

### 2.2 一致性与防击穿

- **失效顺序**：先更新 DB（事务提交）→ Outbox 事件 → 消费者删缓存（先删后异步补）——选用"延迟双删不引入"而以事件驱动删除 + TTL 兜底，最终一致窗口 ≤2s。
- **防击穿**：Caffeine `refreshAfterWrite` 异步刷新 + Redis 侧 `singleflight`（SETNX 锁 200ms）+ 逻辑过期。
- **防雪崩**：TTL 加随机抖动 ±20%；预热脚本发布后执行。
- **防穿透**：空值缓存 60s + 布隆过滤器（不存在的大 ID 拦截，Redis Bloom）。
- **热点探测**：本地 LRU 计数 Top-K（如某村公告被疯读）→ 自动升级到 Caffeine 并延长 TTL。

### 2.3 Redis 部署

- 新建 `infra/szxc-redis`：3 主 3 从（受资源限可 3 主，主节点分别在 175/176 反亲和），maxmemory 6G/节点，`allkeys-lru`，AOF everysec。
- 独立于 dify-plus redis8（租户隔离，C2 确认项）。

## 3. 主数据与数据治理

- **MDM 六实体**：org/party/household/plot/device/sku；黄金记录 + 来源系统字段级 merge 规则；唯一编码：组织=统计局区划码、人=内部 ID（身份证仅存 SM4 密文+尾号索引）。
- **数据质量**： weekly 扫描 6 性规则（如孤儿地块、手机号格式、积分对账差异），报告入 `dws.dq_report`。
- **对账**：积分/预约/兑换三大资金类账户，日终对账作业（TiFlash 批算 vs 流水累计），差异告警。

## 4. 数据服务（Data API）

- 指标定义（口径字典）存 `dws.metric_def`，data-svc 统一暴露 GraphQL `metrics(...)`，防止口径各自为政。
- 数据资产目录：表级/字段级登记 + 分类分级标签 + 血缘（由 AsyncAPI + 变更事件自动织入）。
- 大屏取数：实时件（事件推送计数）+ 批算件（分钟级物化）双轨，页角标注"数据时点"。
